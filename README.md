# 浅浅 qianqian 学习管理智能体 README

## 一、项目概览

- 项目名称：浅浅（qianqian）· 个人学习管理智能体（Web 应用）
- 参赛赛道与命题：中兴赛道 · 学习 DDL 与资料管理智能体
- 目标用户：在多门课程之间管理课件、作业与考试安排的在校学生；也适合助教整理课程资料与截止时间。
- 核心功能摘要：用一句话驱动的学习管理智能体：学科知识解答、课件与讲义讲解（说明依据来源）、日常交流；资料导入与正文抽取；从通知与截图中提取 DDL 并生成提醒；复习计划生成；任务中心；账号隔离与跨设备同步。
- 作品访问方式或运行方式：浏览器访问本机部署的 Web 应用（默认 http://localhost:3000），启动方式见“四、快速开始”。

## 二、运行环境

- 操作系统：Windows 10/11、macOS、Linux 均可。
- 语言与版本：Node.js 22.13 及以上；前端使用 Next.js 16 与 React 19，TypeScript 开发。
- 数据库/向量库/中间件：PostgreSQL 14 及以上（Drizzle ORM 访问，共 10 张表）；未使用向量库，资料检索目前基于关键词匹配。
- 大模型或API依赖：OpenAI 兼容接口（默认 DeepSeek）：一条用于对话与工具调用，另一条用于图片与截图识别。未配置时进入手动模式，其余功能不受影响。
- 硬件或网络要求：普通笔记本电脑即可，无需 GPU；首次安装依赖需要联网；断网时核心功能仍可使用，联网后自动同步。

## 三、目录结构

- 核心目录及作用：
- app/agent：Agent 内核（循环、工具注册表、系统提示词、长期记忆、提醒与主动巡检），纯逻辑、可单元测试。
- app/api：服务端接口（模型代理、文件识别、账号会话、同步、文件、账号管理）。
- app/lib：账号、云同步、模型配置、PDF／Word／PPT 抽取、复习计划、任务与资料逻辑等公共模块。
- app/components：登录页、账号面板、导入队列、片头动画等界面组件。
- db 与 drizzle：数据库表定义、连接封装与数据库迁移脚本。
- scripts：一键初始化、初始化账号、写入预设课件、清理测试账号、重置密码等运维脚本。
- tests：单元测试与端到端测试（含一键运行脚本）。
- worker、build、.openai：构建脚手架，运行所需，请勿删除。

## 四、快速开始

- 依赖安装命令：npm install
- 配置文件准备：复制配置模板并填写数据库地址：cp .env.example .env.local（Windows：copy .env.example .env.local），至少填写 DATABASE_URL。
- 数据库或知识库初始化：npm run setup —— 自动检测数据库连接，必要时建库、建表并创建管理员与两个示例账号（可重复执行）。
- 启动命令：开发模式 npm run dev；正式运行 npm run build && npm start；Windows 也可直接双击 启动浅浅.bat。
- 访问入口或测试账号：http://localhost:3000 ；管理员 admin / admin123，普通用户 student1 / 123456、student2 / 123456（首次登录后请修改密码）。

## 五、配置说明

- 环境变量：必填 DATABASE_URL；可选 DEEPSEEK_API_KEY、DEEPSEEK_API_URL、DEEPSEEK_AGENT_MODEL、DEEPSEEK_EXTRACT_MODEL。
- 模型配置：可在 .env.local 中统一配置，也可由使用者在应用内「设置 → 模型」填写自己的接口；接口地址与密钥为对话、视觉两条链路共用，密钥只保存在本机浏览器。
- 数据路径：浏览器 IndexedDB 保存本地副本；PostgreSQL 保存账号、业务数据与原文件（二进制）。原文件入库后换设备也能直接打开。
- 权限配置：管理员与普通用户两种角色。管理员可新增、停用、重置、删除账号并清理测试账号；普通用户仅能访问自己的数据，业务查询全部按账号过滤。
- 日志配置：服务端接口返回结构化错误信息并在控制台输出；前端在同步、模型调用与导入队列处显示状态；初始化脚本输出数据库检查与迁移结果。

## 六、核心功能

- 功能一：Agent 循环与 14 个工具，同时是学习助手。智能体自主调用查询、记忆与写入三类工具连续完成任务并实时展示思考轨迹；也承担学科知识解答（通用概念直接作答）、课件与讲义讲解（先检索并阅读资料，回答时说明依据来自哪份资料；资料库没有对应材料时如实说明边界）以及日常交流。用户把截图发给她并说“存成资料”时，她会先用 create_course 建好课程（如果需要），再用 create_resource 把这一轮的图片一起存为原文件、并把读到的要点写进正文，写入前照例弹确认卡片。日常对话不会触发任何写入。
- 功能二：资料与 DDL 管理。在课程资料页点「＋ 导入资料」上传 PDF／Word／PPT／图片（也可以让浅浅把对话里的截图存成资料），抽取正文与结构化元数据；一份资料可以挂多份文件，预览里能继续追加、也能单独删除某一份，整份资料的删除按钮在顶部；从课程通知中提取截止时间并生成提醒，支持日历导出。
- 功能三：复习计划。基于课件正文与用户方便学习的时间段生成按天拆分的计划，每条写明使用的资料、重点、复习路线与自测方式，确认后写入任务中心。
- 异常处理与兜底机制：模型未配置或不可用时进入手动模式并明确提示；所有写操作必须用户确认，3 分钟无人确认自动取消；资料无正文时如实说明；支持数据备份与手动录入作为兜底。

## 七、测试方式

- 单元测试：npm run test:agent —— Agent 内核纯逻辑测试（循环、工具注册表、提醒规则、任务分组、同步合并等），共 44 项。
- 接口测试：node tests/e2e-server-api.mjs（账号、会话、云同步、删除传播、账号隔离）与 node tests/e2e-auth-isolation.mjs（多账号数据隔离）。
- 用例集运行方式：npm run test:e2e —— 依次运行全部端到端测试文件（需先启动 npm run dev），覆盖注册登录、资料导入、任务操作、复习计划、跨设备同步与确认卡片等流程。
- 复现抽检说明：按附件 4《评测用例》的操作步骤逐条复现；测试账号由脚本初始化，测试产生的临时账号结束后自动清理。

## 八、常见问题

- 问题现象：① 提示连不上数据库；② 界面显示“手动模式”且智能体不回答；③ 启动时提示端口被占用；④ 预设课件点击“打开原文件”没有反应。
- 可能原因：① PostgreSQL 未启动或 DATABASE_URL 填写有误；② 未配置模型密钥；③ 3000 端口已被占用；④ 课件原件尚未入库。
- 解决方式：① 启动数据库并核对连接串后重新执行 npm run setup；② 在 .env.local 填写模型密钥，或在应用内「设置 → 模型」填写自己的接口；③ 使用 npm run dev -- --port 3200 换端口；④ 执行 npm run db:seed:presets 课件1.pdf 课件2.pdf。
